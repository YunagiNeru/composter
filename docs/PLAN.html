03　検証ツールの構成と実行環境

DEC-002

Windows x64のPython 3.11.14で評価用・実行用の仮想環境を分離した。評価環境は元モデル参照、変換、CPU照合を担当し、軽量実行環境はOpenVINO経由の実機試験を担当する。各実行には対応する環境内のpython.exeを明示する。

固定構成はPyTorch 2.9.1+cpu、Transformers 5.0.0、ONNX Runtime 1.31.0、OpenVINO 2026.4.1系、NumPy 1.26.4等。正確な配布物とハッシュは requirements のロックに記録した。グローバルPython、元モデル、システムドライバーは変更していない。

モデルと評価ケースを固定し、元モデルCPU、OpenVINO CPU、NPUを段階的に実行する。NPUは compile_model(model, "NPU", {"NPU_COMPILER_TYPE":"PLUGIN", "CACHE_DIR":run別ディレクトリ}) で明示指定し、CompiledModelの実コンパイラーと実行先を照合する。AUTO・HETERO・CPU／GPUへの暗黙切替は許可しない。

ネットワーク取得は明示的なprepare段階だけで行い、固定版・リビジョン・サイズ・SHA-256を照合する。通常の参照・変換・推論ではオフライン設定とローカル取得物を使う。未監査の外部セットアップコードは実行しない。

06　日本語データと確認状態

開発用ケース60件は実装側が作成した。各ケースに期待判断、理由、許容解、対象誤り、正解の確認状態を記録している。現在の確認状態は ai_draft_unverified であり、人による正解確認は未実施である。

正式な日本語品質判定：未判定。G1では元モデルをCPUで参照実行し、同じ60件の入力ID、入力ハッシュ、参照結果を保存した。未確認ラベルを使った参考値を正式な精度・合否として扱わない。

未確認ラベルのレビューを待たず、CLI・単体テスト・元モデルCPU参照・CPU変換照合・NPU互換性検査を進める。入力契約またはCPU変換照合に未解決の問題があれば、その問題を残したままNPU結果の正しさを判定しない。明確な日本語品質不適合が人の確認で見つかった場合は、以後の大規模移植・最適化を止めて結果を報告する。

60件はG1用の予備集合だけである。校正・固定評価・通知禁止集合は未作成で、G4品質評価の代替にならない。正解データの追加確認後も、既存結果を上書きせず、新しいRunで記録する。

未確認ラベルへの参考一致：Choice 8/20（40%）、Score 7/20（35%）、Noul 14/20（70%）、合計29/60（48.3%）。AIドラフトへの一致であり、人の正解に対する誤り数ではない。人の確認後にこの集合で調整した場合、同じ集合を最終品質の証明に使わない。確認用の自己完結HTMLには原文・質問・全選択肢・期待判断・理由・許容解・対象誤り・確認状態を記録し、モデル予測を含めていない。

モデルのウォーム推論時間と、トークン化・入力組立・キュー待機・結果整形を含むエンドツーエンド時間を分けて測る。元モデルの同時常駐、結果キャッシュ、不要なプロファイリングが混ざった測定値を軽量実行の代表値にしない。

測定手順と記録条件
観点初期の測定方法案

共存SOMなし／ありで同じ固定CPU負荷をABBA順に比較。NPU競合は別の管理対象プロセスで再現。安全に停止できない他アプリを勝手に起動・終了しない。

電力電力計等の測定がない場合は省電力実証を主張しない。NPU使用率、CPU使用率の低下だけを消費電力へ換算しない。
